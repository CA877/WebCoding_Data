# 70K 数据集构造规划

> 最后更新：2026-06-02

## 目标

7 类任务 × 10K = **70K 训练样本**，刷 WebCompass / Design2Code / Vision2Web / FLAME-VLM-Code 4 个榜单。

所有榜单都不要求远程 URL，训练数据统一用 `assets/` 本地相对路径。

---

## 全流程

```
Phase 1: preprocess/ — 数据获取与清洗（~9h，并行）
├── Pipeline A: WebRenderBench (31,765 项目)
│   入口: pipeline_a_sample_level.py
│   expand → clean → add_js
│
└── Pipeline B: WebCode2M (16K URL)
    入口: pipeline_b_sample_level.py
    前置(可选): filter → preflight
    主处理: crawl → postprocess（保留网站原生 JS）

Phase 1.5: CSS 拆分（TODO）
    extract_css: <style> → styles.css

Phase 2: construct/ — 任务构造（7 类 × 10K）
    construct_webcode2m_dataset.py 统一调度

Phase 3: 验证
    validate_webcode2m_task_dirs.py
```

## Phase 1: Pipeline 使用

### Pipeline A — WebRenderBench

入口: `preprocess/pipeline_a_sample_level.py`

对每个项目：expand（扩展为多页）→ clean（资源本地化）→ add_js（LLM 生成 JS）。每个项目产出 `__original` 和 `__expanded` 两个变体。

```bash
python3 preprocess/pipeline_a_sample_level.py \
  --input-dir /path/to/webrenderbench_projects \
  --output-dir /path/to/output \
  --concurrency 5 --site-timeout 900 --max-pages 7 \
  --browser-proxy socks5://127.0.0.1:13659 \
  --requests-proxy socks5h://127.0.0.1:13659
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--input-dir` | 必需 | 输入项目目录（子目录须含 `index.html`） |
| `--output-dir` | 必需 | 输出目录 |
| `--concurrency` | 5 | 并行 worker 数 |
| `--site-timeout` | 0 | 单样本超时秒数（生产建议 900） |
| `--max-pages` | 7 | 扩展时最多爬取的子页面数 |
| `--wait` | 3000 | 页面加载等待 (ms) |
| `--browser-proxy` | "" | Playwright 浏览器代理 |
| `--requests-proxy` | "" | requests 库代理 |
| `--overwrite` | false | 删除已有输出重新处理 |
| `--no-js` | false | 跳过 JS 生成（默认会生成） |
| `--js-model` | 环境变量 | 覆盖 LLM 模型名 |
| `--js-seed` | 42 | JS 特性选择的随机种子 |

输出：
```
<output-dir>/clean_projects/<project>__original/   # 清洗后的原始项目
<output-dir>/clean_projects/<project>__expanded/   # 扩展+清洗（如成功）
<output-dir>/sample_pipeline_results.jsonl
```

### Pipeline B — WebCode2M

#### 前置过滤（可选，默认跳过）

```bash
# Step 1: URL 质量过滤
python3 preprocess/filter_webcode2m_urls.py \
  --input all_urls.txt --output filtered.txt --rejected-output rejected.tsv

# Step 2: HTTP 可达性检查
python3 preprocess/preflight_webcode2m_urls.py \
  --input filtered.txt --accepted-output passed.txt --rejected-output rejected.jsonl \
  --proxy socks5h://127.0.0.1:13659 --concurrency 50
```

#### 主处理

入口: `preprocess/pipeline_b_sample_level.py`

对每个 URL：crawl（Playwright 爬取）→ postprocess（challenge 检测 + analytics 移除）。保留网站原生 JS，不调用 LLM。支持断点恢复。

```bash
python3 preprocess/pipeline_b_sample_level.py \
  --url-file preflight_passed.txt \
  --output-dir /path/to/output \
  --concurrency 5 --site-timeout 900 \
  --browser-proxy socks5://127.0.0.1:13659 \
  --requests-proxy socks5h://127.0.0.1:13659
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--url-file` | 必需 | URL 列表文件（每行一个 URL） |
| `--output-dir` | 必需 | 输出目录 |
| `--concurrency` | 5 | 并行 worker 数 |
| `--site-timeout` | 0 | 单样本超时秒数（生产建议 900） |
| `--max-pages` | 7 | 每个站点最多爬取的子页面数 |
| `--wait` | 3000 | 页面加载等待 (ms) |
| `--browser-proxy` | "" | Playwright 浏览器代理 |
| `--requests-proxy` | "" | requests 库代理 |
| `--overwrite` | false | 删除已有输出重新处理 |
| `--limit` | 无 | 最多处理多少条 |

输出：
```
<output-dir>/crawled/<project_name>/      # 爬取结果
<output-dir>/quarantined/<project_name>/  # challenge 页面（隔离）
<output-dir>/pipeline_b_results.jsonl     # 增量 manifest
```

### 超时与容错

`--site-timeout N`（N>0）时每个样本在独立 `mp.Process` 中运行，超时后 SIGTERM → SIGKILL → 清理残留。

断点恢复：Pipeline B 自动跳过已处理 URL；Pipeline A 需 `--overwrite` 重跑。

manifest 状态码：`ok` / `partial` / `error` / `site_timeout` / `empty_page` / `failed_index` / `wrong_language` / `challenge_page` / `worker_exited`。

## 服务器运行

入口: `preprocess/run_server.sh`，并行执行 Pipeline A + B。

### 前置配置

```bash
# 1. 环境变量（必需）
export HTTP_PROXY_URL=http://your-proxy:port
export OPENAI_API_KEY=your-key
export OPENAI_BASE_URL=https://your-api-endpoint
export OPENAI_MODEL=your-model
export CONDA_ENV=lora  # 可选，默认 lora

# 2. 依赖
pip install playwright beautifulsoup4 requests openai python-dotenv
playwright install chromium

# 3. 运行
cd /path/to/project/root
bash preprocess/run_server.sh
```

### 可配置变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `CONCURRENCY_A` | 80 | Pipeline A 并发 |
| `CONCURRENCY_B` | 50 | Pipeline B 并发 |
| `SITE_TIMEOUT` | 900 | 单样本超时秒数 |
| `PIPELINE_A_INPUT` | `datasets/webrenderbench_projects` | A 输入目录 |
| `PIPELINE_A_OUTPUT` | `datasets/pipeline_a_output` | A 输出目录 |
| `PIPELINE_B_URL_FILE` | `datasets/webcode2m_preflight_passed_urls.txt` | B 输入 URL 文件 |
| `PIPELINE_B_OUTPUT` | `datasets/pipeline_b_output` | B 输出目录 |
| `PIPELINE_B_URL_LIMIT` | 16000 | B 取前 N 个 URL |
| `RUN_PREFLIGHT` | 空 | 设为 1 跑 filter + preflight |
| `NO_JS` | 空 | 设为 1 跳过 JS 生成 |
| `SKIP_PIPELINE_A` / `SKIP_PIPELINE_B` | 空 | 设为 1 跳过对应 Pipeline |

### 产出估算（并发 A=80 / B=50）

| Pipeline | 输入量 | 预计可用产出 | 耗时 |
|----------|--------|-------------|------|
| A | 31,765 项目 | ~36,000（原始+扩展） | ~8.8h |
| B | 16,000 URL | ~9,760 | ~9.1h |
| **合计** | — | **~46K 项目** | **~9.1h（并行）** |

46K 项目 × 1.5-2 任务/项目 = **70K-92K 训练样本**。

## Phase 2: 任务构造

CSS 拆分后，底层项目结构：`index.html` + `styles.css` + `main.js` + `resources/`。

用 `construct/construct_webcode2m_dataset.py` 统一构造 7 类任务：

```
底层项目
├─→ text-generation:   截图 → VLM 生成 PRD → (PRD, code)
├─→ image-generation:  截图 → (screenshots, code)
├─→ video-generation:  录制视频 → (video, code)
├─→ text-editing:      LLM 合成编辑需求 → (src, edit_request, dst)
│     └─→ image-editing:   对 src/dst 截图 → (screenshots, edit_request, dst)
└─→ text-repair:       LLM 注入缺陷 → (broken, desc, fixed)
      └─→ image-repair:    对 broken/fixed 截图 → (screenshots, desc, fixed)
```

## 硬约束

3. JS 必须有（WebCompass / Vision2Web 考察交互）
4. CSS 必须拆分为 `styles.css`（WebCompass 要求）
