## 2. 主要结论

当前发布数据存在几类明确质量问题：

1. **非中英文页面确实存在**：基于 HTML `lang=` 属性的确定性线索，约 6.9%-7.6% 样本含明显非 zh/en 的 lang 标记。
2. **成人/博彩/约会风险路径存在**：基于 `instance_id` / 域名路径的严格统计，`image-generate` 有 30 条，`image-repair` 有 19 条。基于全文关键词的宽松统计会有很多误报，不能直接作为删除依据。
3. **image-edit 的 patch 监督严重不可靠**：只有 28.57% 样本的所有 patch search 能在输入代码中唯一匹配；71.22% 至少有一个 patch search 找不到。
4. **image-repair 的 patch 监督明显好很多，但仍有问题**：94.04% 样本 patch search 全部唯一匹配；3.90% 至少有一个找不到，2.06% 至少有一个多重匹配。
5. **text-edit/text-repair 发布 JSONL 缺少 `input_files`**：因此无法从发布文件直接验证 patch 是否唯一匹配。需要回到 unified 中间数据或重新发布带代码版本来检查。
6. **远程 URL 大量残留**：各任务中 98%-99% 行命中远程 URL。这里包含允许的图片替代 URL，也可能包含不该存在的 CSS/JS/font 远程依赖，需要进一步区分白名单。
7. **captcha/challenge、parked/占位页有明显线索**：grep 统计是保守线索，仍需二次精筛。

统计方法：逐行 grep HTML `lang=` 属性；`en/zh/zh-CN/zh-Hans/zh-Hant` 以外计为 likely non zh/en。  
这是“确定性线索”，没有 `lang=` 或页面标错语言的样本不会被覆盖。

建议：

- 发布前增加 language gate。
- 第一层用 `lang=`、域名/TLD、页面正文脚本比例做快速筛选。

### 4.2 宽松全文关键词统计

全文关键词统计会扫代码、instruction、metadata、图片 URL 等所有文本，因此会误伤，例如：

- `bet` 命中普通单词或 URL 片段；
- `placeholder` 命中正常表单属性；
- `sex` 命中 `adoptionformsexpress` 这类非成人词片段。

所以本报告不把宽松全文统计作为直接删除比例，只作为“需要二次精筛”的线索来源。

建议：

- adult/casino/dating 黑名单应优先作用于 URL、域名、路径、title、h1，而不是全量代码字符串。
- 需要人工抽查黑名单规则，避免 `adult literacy`、`sexpress` 等误杀。
- 确定命中成人/博彩/escort/call-girls/porn 的样本应直接剔除。

## 5. Patch 可执行性统计

统计方法：只检查有 `input_files` 的发布文件，即 `image-edit.jsonl` 和 `image-repair.jsonl`。对每个 patch 的 `search` 检查是否在对应输入文件中出现且只出现一次。

| 文件 | total | all unique | any search not found | any ambiguous | any path missing |
|---|---:|---:|---:|---:|---:|
| `image-edit.jsonl` | 4,333 | 1,238 (28.57%) | 3,086 (71.22%) | 10 (0.23%) | 0 (0.00%) |
| `image-repair.jsonl` | 4,845 | 4,556 (94.04%) | 189 (3.90%) | 100 (2.06%) | 0 (0.00%) |

关键问题：

- `image-edit` 的 patch 监督基本不能直接信任。71.22% 样本至少有一个 search 在输入代码中找不到。
- `image-repair` 相对健康，但仍有约 5.96% 样本存在 not found 或 ambiguous。
- 发布版 `image-edit/image-repair` 没有 `output_files`，所以只能检查 search 端，无法检查 replace 是否真的存在于输出代码。
- 发布版 `text-edit/text-repair` 没有 `input_files`，所以 patch 完全无法在发布 JSONL 上复核。

建议：

- edit/repair 发布前必须以 unified 中间数据做 patch gate：
  - `path` 必须存在；
  - `search` 必须唯一匹配 input code；
  - 应用 patch 后应得到 output code；
  - `replace` 应能在 output code 中找到；
  - 不满足的样本进入 rejected JSONL。
- `image-edit` 应回到构造链路检查：为什么截图版保留的 input code 与 patch search 不一致。可能原因包括图片 URL rewrite、代码归一化、发布前清洗改动了 input code，但 patch 没同步更新。

## 6. 字段/发布格式问题

### 6.1 `input_files` 缺失

grep 统计：

| 文件 | missing `input_files` |
|---|---:|
| `text-edit.jsonl` | 4,333 (100.00%) |
| `text-generate.jsonl` | 4,959 (100.00%) |
| `text-repair.jsonl` | 4,926 (100.00%) |
| image 三类 | 0 (0.00%) |

解释：

- 对 generation 来说，缺 `input_files` 不一定是问题。
- 对 `text-edit` / `text-repair` 来说，缺 `input_files` 会导致发布数据无法自检 patch 可执行性。

### 6.2 `output_files` 缺失

image patch 深查显示：

- `image-edit`: `missing_output_files = 4,333 (100%)`
- `image-repair`: `missing_output_files = 4,845 (100%)`

这意味着发布版 image edit/repair 只能检查输入侧 patch search，无法检查输出侧 replace。

建议：

- 训练发布版可以不一定保留完整 `output_files`，但质量审计版必须保留。
- 至少应保留一个 `audit/` 目录，包含同批样本的 full unified JSONL，便于复查。

## 7. 远程 URL 残留

全量 grep 统计显示各文件远程 URL 命中率接近 99%。这不是全都错误，因为当前补救逻辑允许 `loremflickr.com` 作为替代图源；但它说明现在还没有区分：

- 可接受：白名单图片替代 URL；
- 不可接受：远程 CSS、JS、font、video、iframe、第三方 tracking；
- 需复核：页面正文中的普通链接。

建议：

- 将 remote URL 检查拆成白名单和黑名单：
  - allowlist: `loremflickr.com` 等明确允许的图片替代源；
  - reject: `.css`、`.js`、font、iframe、analytics、video；
  - neutralize: 普通 `<a href>`。
- 质量报告中分别统计 remote image / remote script / remote stylesheet / remote font / remote link。

## 8. captcha/challenge 与 parked/占位页

已有 grep 统计显示大量线索，但需要注意：

- `captcha` 可能出现在功能说明或 JS 变量里；
- `placeholder` 可能只是 HTML input placeholder；
- 因此这两类不能用当前 grep 比例直接删除。

建议用更精确规则：

- challenge/captcha：匹配 title/body 中的 `Just a moment`、`Checking your browser`、`Cloudflare`、`Access denied`、`verify you are human`。
- parked/domain-for-sale：匹配 title/h1/body 主文本中的 `domain for sale`、`buy this domain`、`parked domain`、`under construction`。
- 表单属性里的 `placeholder=` 不应计入 parked/占位页。
