# WebCode2M 扩展多页方案

## 当前原则

1. 多页必须来自真实站内 HTML 链接。
2. 不模板造页，不凭空加 `page_1.html`。
3. 子页抓取后走同一套 WebCode2M 官方清洗逻辑。
4. 扩展失败就保留 single，不硬凑 multipage。
5. 当前正式 7x10 使用已清洗的多页项目作为输入。

## 已完成

1. 下载并接入官方 WebCode2M 清洗代码：`third_party/naturalcc/examples/webcode2m`。
2. `webcode2m_clean_pipeline.py` 调用官方 `formatHtml` / `formatCss` / `mergeHtmlCss`。
3. 首页和子页都使用同一套官方清洗流程。
4. 子页来源是原网页中的站内跳转链接。
5. 清洗后移除远程渲染依赖，保留本地 assets。
6. 清理 provenance 文件，不把 `metadata.json`、原始截图等放进训练样本。
7. 已生成多页样本：
   - `WebCoding_Data/local_trials/webcode2m_official_multipage_10`
   - `WebCoding_Data/local_trials/webcode2m_official_multipage_seed15`

## 多页扩展流程

1. 读取原始 WebCode2M HTML。
2. 抽取首页里真实 `href`。
3. 只保留同站 HTML 子页。
4. 过滤登录、注册、购物车、隐私、条款、cookie、feed、admin、广告活动等低价值链接。
5. 下载子页 HTML。
6. 子页进入官方 WebCode2M 清洗。
7. 重写已下载子页的站内链接为本地文件。
8. 输出为：

```text
index.html
page_1.html
page_2.html
...
assets/
```

## 后续规则

1. 扩大规模时优先从能真实爬到站内子页的 WebCode2M 样本里取。
2. 不能把无 HTML 的资源目录当样本。
3. 进入七类任务前必须跑 validator。
