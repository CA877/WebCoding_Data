# 0917 数据集探索

总的原则：

- 本质思路：浏览器 + LLM 建能力库：从真实操作中发现能力，保证任务有来源。
- 复杂任务应该按照“同一个业务对象”进行组合。
- 尽量利用别人已经整理好的源码、示例、测试或操作轨迹，让 LLM 做抽取，减少重新跑浏览器的成本。

## 1. PatternFly React

### 性质
PatternFly React 是一个网页组件库.

原始组织大概是：
PatternFly React
└── Accordion
    ├── 组件源码
    │   ├── Accordion.tsx
    │   ├── AccordionItem.tsx
    │   ├── AccordionToggle.tsx
    │   └── AccordionContent.tsx
    │
    ├── examples
    │   ├── AccordionSingleExpandBehavior.tsx
    │   ├── AccordionFixedWithMultipleExpandBehavior.tsx
    │   ├── AccordionBordered.tsx
    │   └── AccordionToggleIconAtStart.tsx
    │
    └── __tests__
        ├── AccordionToggle.test.tsx
        ├── AccordionContent.test.tsx
        └── AccordionItem.test.tsx

可以从不同的React示例文件中获取部分原子能力，同时也可以从tests进行能力的补充。

### 如何变成任务？
（1）把各种源码、示例和测试，统一翻译成相同字段的能力卡：从观察到的行为，让LLM：“请把相关行为合并成一个完整功能，不要拆成多个小功能。“

（2）记录到能力卡上，进入灵感库。
