# WebCoding 灵感挖掘

灵感挖掘是开放式发现过程，不为每个来源预设必须寻找的目标能力。WebCompass 16 类及其他案例只用于说明理想任务粒度和启发观察范围，不能作为逐网页检索清单、命中要求或机械分类模板。来源记录中已有的 `target_edit_types`、`primary_edit_target`、`expected_observations` 和 `mining_focus` 只视为历史候选池的举例与来源说明，不得限制浏览器探索、强迫模型寻找对应行为，或把未观察到的期待写成网页事实。

浏览器应从页面实际呈现出发，优先进入演示组件及 iframe 内的真实内容，自主发现有迁移价值的交互特色、功能特色、状态联动、用户流程、视觉风格、响应式变化和信息组织方式。Header、Support、文档导航和代码工具栏等外围区域仅在它们本身构成页面主要特色时记录。

每张灵感卡在建库时形成一个完整的组件级或流程级任务，粒度大致与 WebCompass 的完整 Edit 类型相当，也允许同等粒度的新类型。同一组件、同一业务对象上的相关控件、操作、共享状态、反馈、布局和无障碍行为合并成一张卡；例如表格的选择、增删、排序、筛选、分页和展开详情共同描述一个数据表格功能，不按按钮或单次动作拆卡。只有不同组件系统或不同端到端用户流程才分卡。

所有内容以真实浏览器观察为准。交互功能需要实际触发及有意义的结果；视觉或动效特色需要对应的视觉、时间或滚动状态证据。只观察到静态说明、孤立属性、普通输入框、单个开关、空容器、安装示例或未进入的 iframe 时，不为凑数量生成卡片；该来源允许输出空卡并继续下一来源。

保持现有输入和输出接口不变：输入仍为 URL 或物理机本地项目，输出仍使用现有 capability pool、产品流程及可选参考代码结构。单个来源访问失败、无完整特色或返回空卡时保留记录并继续整批；批处理、代理、重试和凭据规则遵循项目 `AGENTS.md`。

当前实现与运行细节见 [灵感库构造文档](docs/inspiration_library.md)。用户要求修改流程时，先更新相关实现，再按项目规则跑真实浏览器与 LLM 小样本；用户只要求维护 skill 时，仅修改并校验本 skill，不启动实现、测试样本或批量任务。

## 文档索引与当前口径

- `docs/README.md`：入口、连续 Edit Session、代码阅读顺序和测试命令。
- `docs/inspiration_library.md`：URL/本地项目输入、`capability_pool` 输出、closure-aware 采集和卡片完成口径。
- `docs/Webcompass_edit-types.md`：16 类能力的参考 taxonomy；只用于理解粒度和事后分类，不是检索配额。
- `docs/数据集探索.md`：具体来源的探索记录，属于观察证据，不升级为全局规则。
- `runs/`：一次运行的源码、响应和状态；生成的 `AGENTS.md` 只约束对应嵌套项目。

灵感卡必须来自真实浏览器动作和可复核证据；静态文档、未进入 iframe、空容器或普通控件不构成能力证据。卡片是组件级或流程级任务，不按单个按钮拆分。失败来源保留记录并继续，不因单个来源失败停止批次。
