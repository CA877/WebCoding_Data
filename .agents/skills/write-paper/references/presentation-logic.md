# WebCoding 论文呈现方案：完整逻辑

## 一句话主线

借助真实网页的功能灵感，改变一个网页的主任务，继而重新组织它的交互方式与界面结构；整个变化通过一串可验证的功能级 Edit 完成，最终得到与原项目明显不同、但具有技术继承关系的新前端项目。

这是一项研究构想。数据质量与训练收益必须由后续实验验证。

## 功能灵感条目

一条条目不是“地图、筛选、编辑、侧栏”等抽象名词，而是有界面、有动作、有状态变化、有实现参考的案例：

```text
功能：在地图上选择对象，并在详情侧栏中编辑它。
用户操作：点击地图标记 → 侧栏显示对应对象 → 修改信息并保存 → 标记和详情同步更新。
界面证据：操作前后截图或交互录屏。
实现参考：相关组件、事件处理、状态更新代码及必要上下文。
```

## Pipeline

```text
Seed：项目代码 + 实际渲染页面 + 交互记录
  ↓ 结合功能灵感，寻找有技术承接关系的新主任务
明确目标用户的界面操作流程
  ↓ 按当前网页状态推荐下一项功能灵感
将灵感具体化为当前项目的 Edit Query
  ↓ 修改代码，并在浏览器中检查视觉与交互结果
接受新状态，保存对应 diff，再推荐下一步
  ↓ 新前端产品 + 可监督编辑轨迹
```

## 贯穿示例：房源浏览站到房东运营工作台

初始项目服务租客：在已有房源中寻找适合自己的房子，具有列表、筛选、详情和收藏。目标项目服务房东：管理发布的房源、修改信息并控制展示状态。

| 步骤 | 功能级 Edit | 前端变化 |
| --- | --- | --- |
| 1 | 新增可独立访问的房东管理工作区，保留浏览入口 | 新角色与操作入口，复用既有房源展示 |
| 2 | 增加房源编辑侧栏，保存后更新房源信息 | 只读详情变成可编辑界面，表单与展示联动 |
| 3 | 增加发布状态切换，并同步管理列表与侧栏 | 用户控制对象的展示状态 |
| 4 | 新增地图工作视图作为默认视图，保留列表切换 | 主区由网格转为空间视图 |
| 5 | 地图选择与编辑侧栏联动；编辑后同步标记与列表 | 形成连续运营操作流程 |

最终项目以地图和编辑侧栏为核心，但不要求推倒重写：原有房源对象、部分展示组件、筛选和状态管理可继续发挥作用。

## 多模态与验证

训练中的多模态 Edit 可表示为：

`(当前代码, 当前界面截图, 功能指令) → 代码 Diff`

验证至少覆盖：选中对象是否正确、保存后相关区域是否同步、目标交互是否可真实操作、原有应保留功能是否仍有效。视觉与行为过程一并保存。生成样本的完整需求只能描述当前实际已实现状态；不可把计划功能写入样本。

## 可复用论文段落

> 我们研究如何在保留前端工程承接关系的条件下，通过连续功能编辑获得视觉与交互上显著不同的新网页。系统借助真实网页的功能灵感，确定新的主任务，并逐步重组现有数据的展示、编辑与操作关系。主任务变化推动交互方式与界面结构变化，而每一步都被实例化为具有视觉和行为证据的功能指令及代码补丁。最终，一条连贯的网页演化轨迹，同时提供局部可监督的编辑样本与整体差异显著的生成样本。

待验证的研究假设是：模型在技术承接、但界面组织与操作流程显著不同的网页之间学习，比重复生成外观相近、功能孤立的变体，更有利于前端生成与编辑能力提升。
